## 31. Desfășurări `runtime`: pipeline-ul sursă → bytecode, JIT, tipare dinamică și puternică, type hints, AOT, reference counting și GC, import și `__name__`; comparațiile cu C++ (tichetul 15; verificat 3 noiembrie 2026)

Python rulat pe 3.13.16 (cele 8 blocuri din `src/desf/runtime.md` rulează în `node tools/desf_examples.mjs`; unele afirmații au rulat și pe 3.12). Docs.python.org servește acum documentația pentru 3.15.2, deci faptele de versiune sunt verificate pe paginile „What's New” 3.13, 3.14 și 3.15. C++ verificat în draftul N4659 (timsong-cpp.github.io/cppwp/n4659; cppreference răspunde 403 din mediul de lucru) și prin compilare cu `g++ 13.3` și `clang++ 18.1` în `-std=c++17` (`-Wall`). FastAPI 0.162.0, Pydantic 2.13.5 și Uvicorn 0.54.0 sunt cele din mediul de lucru.

- ✅ **Compilarea se face pe tot fișierul, înainte de execuție**: un `SyntaxError` la rândul 4 al unui script oprește programul înainte să ruleze rândul 1 (rulat: `print("rândul 1")` nu afișează nimic). `ast.parse` produce un AST, iar „An abstract syntax tree can be compiled into a Python code object using the built-in `compile()` function”; „Code objects can be executed by `exec()` or `eval()`” (https://docs.python.org/3/library/ast.html, https://docs.python.org/3/library/functions.html). Rulat: `ast.parse("1 + 2", mode="eval")` → `compile(t, "<s>", "eval")` → obiect de tip `code`, iar `eval(c)` dă `3`.
- ✅ **`.pyc`**: „Python caches the compiled version of each module in the `__pycache__` directory under the name `module.version.pyc`”; „it always recompiles and does not store the result for the module that's loaded directly from the command line”; „A program doesn't run any faster when it is read from a `.pyc` file than when it is read from a `.py` file; the only thing that's faster about `.pyc` files is the speed with which they are loaded.” Sursă: https://docs.python.org/3/tutorial/modules.html. Rulat: `python3 main.py` cu `import mod` creează doar `__pycache__/mod.cpython-313.pyc`, nu și un `.pyc` pentru `main.py`. `PYTHONDONTWRITEBYTECODE` (non-vid): „Python won't try to write `.pyc` files on the import of source modules” (echivalent cu `-B`; https://docs.python.org/3/using/cmdline.html).
- ✅ **Bytecode-ul nu e portabil**: „Bytecode is an implementation detail of the CPython interpreter. No guarantees are made that bytecode will not be added, removed, or changed between versions of Python” (https://docs.python.org/3/library/dis.html); glosarul: „bytecodes are not expected to work between different Python virtual machines, nor to be stable between Python releases” (https://docs.python.org/3/glossary.html#term-bytecode).
- ✅ **Bucla de evaluare e cod C**: `Python/ceval.c` conține `_PyEval_EvalFrameDefault`, cu salturi prin tabel (`USE_COMPUTED_GOTOS`) sau, cu `_Py_TAIL_CALL_INTERP`, apeluri în coadă (sursa din `python/cpython`, ramura `main`). ⚠️ Pagina python.org/download/alternatives nu spune „scris în C”; afirmația „CPython e un program scris în C” se sprijină pe fișierele sursă `.c` și pe punctul 2 al fișei.
- ✅ **JIT experimental**: 3.13: „A basic JIT compiler was added. It is currently disabled by default”; se construiește cu `--enable-experimental-jit`, iar cu valoarea `yes-off` „To enable the JIT at runtime, pass the environment variable `PYTHON_JIT=1`” (https://docs.python.org/3/whatsnew/3.13.html). 3.14: „The official macOS and Windows release binaries now include an experimental just-in-time (JIT) compiler. Although it is not recommended for production use, it can be tested by setting `PYTHON_JIT=1`”; „Free-threaded builds do not support JIT compilation” (https://docs.python.org/3/whatsnew/3.14.html). `PYTHON_JIT`: „On builds where experimental just-in-time compilation is available, this variable can force the JIT to be disabled (`0`) or enabled (`1`)”, adăugat în 3.13 (cmdline). Rulat: pe 3.13.16 din mediu `sys._jit` nu există. ⚠️ Pentru 3.15 „What's New” spune „The experimental JIT compiler has been significantly upgraded”, dar paginile citite nu spun dacă e pornit implicit; desfășurarea spune doar „oprit în build-urile obișnuite” (adevărat pentru 3.13 și 3.14).
- ✅ **Tipare dinamică**: „Names refer to objects”; „Name resolution of free variables occurs at runtime, not at compile time” (https://docs.python.org/3/reference/executionmodel.html). Rulat: `x = 1; x = "unu"` dă `type(x).__name__ == 'str'`; o funcție cu `"1" + 1` pe o ramură neapelată se definește fără eroare, iar `f(False)` ridică `TypeError`; `compile("def f(): return 'a' + 1", ...)` reușește și eroarea apare abia la `f()`.
- ✅ **Tipare puternică**: rulat: `"1" + 1` ridică `TypeError: can only concatenate str (not "int") to str`; `"1" * 3` dă `'111'` (repetare, nu conversie), `1 + 2.5` dă `3.5`, `True + 1` dă `2`, `int("1") + 1` dă `2`. JavaScript (rulat în Node 22): `"5" + 1` dă `"51"`. ⚠️ Distincția „dinamic = când se verifică tipurile, puternic = cât de ușor se amestecă” e definiția obișnuită; pagina din wiki.python.org care o formulează a răspuns 404 din mediul de lucru, deci nu are citat.
- ✅ **Type hints**: „The Python runtime does not enforce function and variable type annotations. They can be used by third party tools such as type checkers, IDEs, linters, etc.” (https://docs.python.org/3/library/typing.html). Rulat: `def f(x: int) -> int` cu `f("a")` întoarce `'a'`; `f.__annotations__["x"]` e `int`, iar `int("5")` dă `5`. Până la 3.13 expresia adnotării se evaluează la `def`: rulat pe 3.13 și 3.12, `def f(x: Lipsa)` ridică `NameError`, iar `x: "Lipsa"` merge și lasă șirul în `__annotations__`. 3.14 (PEP 649 / 749): „annotations … are no longer evaluated eagerly” (whatsnew 3.14). FastAPI 0.162.0 + Pydantic 2.13.5, rulat cu `TestClient`: `GET /n/abc` la `def n(x: int)` dă **422** cu `type: int_parsing`, iar `/n/5` dă 200 și `{"x": 5}` (secțiunea 5 are faptele FastAPI / Pydantic).
- ✅ **Memorie**: glosar: „Python performs garbage collection via reference counting and a cyclic garbage collector”; „When the reference count of an object drops to zero, it is deallocated”; „Some objects are immortal and have reference counts that are never modified”; „reference counts are not considered to be stable or well-defined values” (glossary). Data model: „CPython currently uses a reference-counting scheme with (optional) delayed detection of cyclically linked garbage, which collects most objects as soon as they become unreachable, but is not guaranteed to collect garbage containing circular references”; „Do not depend on immediate finalization” (https://docs.python.org/3/reference/datamodel.html). `gc`: „The GC classifies objects into three generations”; collecția pornește din generația 0 (https://docs.python.org/3/library/gc.html); `del x` doar scade contorul (data model, nota de la `__del__`). Rulat (3.13.16, `gc.disable()` pentru determinism): un obiect cu `n.me = n`, după `del n`, are `weakref` încă viu (`w() is None` → `False`); după `gc.collect()` → `None`. `gc.get_threshold()` dă `(2000, 10, 10)` pe 3.13.16.
- ⚠️ **GC pe versiuni**: 3.14.0–3.14.4 au livrat un GC **incremental**; din **3.14.5** (și în 3.15) s-a revenit la cel generațional din 3.13, din cauza consumului de memorie (https://docs.python.org/3/whatsnew/3.14.html, secțiunea „Garbage collection”; https://docs.python.org/3/whatsnew/3.15.html, modulul `gc`). Desfășurarea spune „generațional”, adevărat pe 3.13 și pe 3.14.5+; nu pomenește perioada 3.14.0–3.14.4. Build-ul free-threaded n-a fost verificat.
- ✅ **C++: `shared_ptr`**: „shared_ptr implements semantics of shared ownership; the last remaining owner of the pointer is responsible for destroying the object”; `use_count()`: „The number of shared_ptr objects, *this included, that share ownership with *this” ([util.smartptr.shared]). Compilat (g++ 13.3 și clang++ 18.1): `make_shared<N>()` + copie dă `use_count()` 1, apoi 2, iar destructorul rulează la ieșirea din scope; `a->me = a` (`shared_ptr<N>` în `N`) dă `use_count()` 2 și destructorul **nu** rulează niciodată (nu apare „del”); cu `weak_ptr<M> me`, `use_count()` rămâne 1 și destructorul rulează.
- ✅ **C++: compilare**: faza 7 „The resulting tokens are syntactically and semantically analyzed and translated as a translation unit”; faza 9 „All external entity references are resolved … All such translator output is collected into a program image” ([lex.phases]). Compilat: `std::string s = "a"; int n = s + 1;` dă `no match for 'operator+' (operand types are 'std::string' … and 'int')`; `auto x = 1; x = "unu";` dă `invalid conversion from 'const char*' to 'int'`.
- ✅ **C++: conversii implicite**: compilat și rulat (g++ și clang++): `const char* p = "1" + 1;` compilează fără avertisment (`-Wall`) și `p` arată spre terminatorul `'\0'` (șir gol: `[]`); `'a' + 1` dă `98`, `1 + 2.5` dă `3.5`; `std::string("1") + '1'` dă `"11"` (cu `char`), iar `std::string("1") + 1` nu compilează.
- ✅ **C++: erori de tip la runtime**: `std::any x = 1; std::any_cast<std::string>(x);` aruncă `std::bad_any_cast`; `dynamic_cast<E*>(p)` pe un `D*` (ambele derivate din `B` cu `virtual`) dă `nullptr` (compilat și rulat). `std::vector<int> v(3); v[10]` compilează fără avertisment cu `g++ -Wall` și `clang++ -Wall` (nu s-a rulat: comportament nedefinit).
- ✅ **C++: `main` și inițializarea globală**: „The function main shall not be used within a program” ([basic.start.main]); inițializarea dinamică a variabilelor globale e „sequenced before the first statement of main or is deferred”, iar între unități de traducere ordinea e „indeterminately sequenced” ([basic.start.dynamic]); `#include` „causes the replacement of that directive by the entire contents of the header” ([cpp.include]). Compilat: un obiect global cu constructor afișează `global ctor` înainte de `main`; un `puts("x");` la nivel de fișier dă `expected constructor, destructor, or type conversion before '(' token`.
- ✅ **Import și `__name__`**: „They are executed only the first time the module name is encountered in an import statement. (They are also run if the file is executed as a script.)” (tutorial, modules); `sys.modules` „serves as a cache of all modules that have been previously imported”, iar dacă numele e acolo „the associated value is the module satisfying the import, and the process completes” (https://docs.python.org/3/reference/import.html); „if the module is executed in the top-level code environment, its `__name__` is set to the string `'__main__'`”, iar idiomul există pentru că altfel „the script code would unintentionally execute” la import, de exemplu într-un test (https://docs.python.org/3/library/__main__.html). Rulat (3.13): `m.py` cu `print('run', __name__)` afișează `run m` la primul `import m` și nimic la al doilea; `"m" in sys.modules` e `True`; `print(__name__)` în scriptul principal dă `__main__`. Un fișier `a2.py` care importă `b2`, care importă `a2`, pornit cu `python3 a2.py`, își execută corpul de două ori (`a2 body a2`, apoi `a2 body __main__`). `python3 -m uvicorn srv:app` (Uvicorn 0.54.0) importă `srv` (corpul afișează `body, __name__ = srv`) și nu rulează blocul `if __name__ == "__main__"`.
- ⚠️ **Nerulat, doar din cunoaștere sau documentație**: „în imaginile Docker se setează des `PYTHONDONTWRITEBYTECODE=1`” (practică frecventă, nu fapt din docs; variabila e documentată); `e.target.value` e mereu șir în React (proprietatea `value` a unui `input` din DOM e un șir); TypeScript: `tsc` oprește build-ul la erori de tip și emite JavaScript fără tipuri (desfășurarea 6 nu afirmă nimic despre `noEmitOnError`).

**Erori de fapt în punctele fișei `runtime`**: niciuna găsită; punctele nu au fost modificate. Cele 8 puncte au fost recitite față de sursele de mai sus și față de rulări. Precizări, nu erori: la punctul 1, doar modulele **importate** se salvează ca `.pyc`; scriptul pornit direct se recompilează de fiecare dată; la punctul 2, „JIT oprit implicit” e valabil pentru build-urile obișnuite 3.13 și 3.14 (binarele oficiale macOS / Windows din 3.14 îl includ, dar pornesc doar cu `PYTHON_JIT=1`), iar 3.15 l-a îmbunătățit (starea implicită nu a fost confirmată); la punctul 3, `TypeError` apare la rulare pentru că **compilarea** în bytecode verifică doar sintaxa; la punctul 5, „ignorate de interpretor” înseamnă „nu sunt verificate”: până la 3.13 expresia hint-ului se evaluează la `def` (`NameError`), din 3.14 leneș; la punctul 6, „erorile de tip nu ajung în producție” se referă la erorile prinse de verificarea de tipuri; compilatorul C++ nu prinde depășirile de index, comportamentul nedefinit și cast-urile greșite făcute la runtime; la punctul 7, „GC generațional” e adevărat pe 3.13 și pe 3.14.5+ (3.14.0–3.14.4 au avut unul incremental), iar „eliberare imediată” e detaliu al CPython, nu garanție a limbajului (și există obiecte „immortal”, fără eliberare); la punctul 8, cauza gărzii `__name__` e că importul execută corpul modulului; cache-ul din `sys.modules` doar împiedică repetarea, iar un fișier pornit ca script și importat apoi rulează de două ori.
