## 41. Desfășurări `graphql`: schemă și operații, over-fetching, N+1 și DataLoader, Strawberry / Graphene / Ariadne, erori și HTTP, limite și autorizare, `@deprecated` (tichetul 21; verificat 3 noiembrie 2026)

Python rulat pe 3.13.16 cu strawberry-graphql 0.339.1 (aceeași versiune ca în secțiunea 14 și ca pe strawberry.rocks pe 3 noiembrie 2026) și graphql-core 3.3.1; cele 3 blocuri `python` din `src/desf/graphql.md` sunt simulări fără biblioteci și rulează în `node tools/desf_examples.mjs`, iar cele 4 blocuri `text` (SDL, query, cod Strawberry cu schema generată) sunt verificate de mână, cu ieșirile Strawberry de mai jos. Fără C++: modulul nu are echivalent real. Specificația citită: GraphQL, ediția September 2025 (https://spec.graphql.org/September2025/); GraphQL over HTTP, „Current Working Draft” (http://http-spec.graphql.org/draft/, fără dată pe pagină).

- ✅ **Operații și schemă** (spec, §2.4): „query – a read-only fetch.”, „mutation – a write followed by a fetch.”, „subscription – a long-lived request that fetches data in response to a sequence of events over time.” graphql.org (https://graphql.org/learn/schema/): „Every GraphQL schema must support `query` operations”, `Mutation` și `Subscription` sunt opționale, iar cererile „are validated and executed against that schema”. `String!` = tip Non-Null: „the GraphQL service promises to give you a value whenever you query this field”. Endpoint: „a GraphQL server operates on a single URL/endpoint, usually `/graphql`” (https://graphql.org/learn/serving-over-http/).
- ⚠️ **Over-fetching / under-fetching**: termenii nu apar pe graphql.org (paginile „Introduction to GraphQL” și „Performance” nu îi folosesc); sunt jargon obișnuit. Lecția 3 de pe graphql.org spune că GraphQL te lasă să ceri „exactly the data you need — including fields, variables and fragments”. Desfășurarea definește termenii în propoziție, ca pe jargon, nu ca pe un citat.
- ✅ **N+1 și DataLoader** (https://graphql.org/learn/performance/): „This is known as the N+1 problem, where an initial request to an underlying data source (for a hero's friends) leads to N subsequent requests to resolve the data for all of the requested fields”; soluția: „a batching technique, where multiple requests for data from a backend are collected over a short period and then dispatched in a single request … by using a tool like Facebook's DataLoader”. Strawberry (https://strawberry.rocks/docs/guides/dataloaders): `DataLoader(load_fn=…)`, „by default DataLoader caches the loads”, loaderul se creează „when creating the GraphQL context so that it only caches results with a single request”. Rulat (0.339.1): `await asyncio.gather(l.load(1), l.load(2), l.load(2), l.load(3))` cheamă `load_fn` o singură dată, cu `[1, 2, 3]` (cheia 2 apare o singură dată), iar `load_fn` care întoarce `None` pe poziția cheii 3 dă `None` rezultatului; un `load(1)` ulterior nu mai cheamă `load_fn`. „În același moment al event loop-ului” e deducția din acest rezultat (documentația nu vorbește despre tick).
- ✅ **Strawberry, Graphene, Ariadne**: Strawberry „is built on top of Python's dataclasses and type hints functionality” (https://strawberry.rocks/docs); integrare FastAPI: `from strawberry.fastapi import GraphQLRouter`, `GraphQLRouter(schema)`, `app.include_router(graphql_app, prefix="/graphql")` (https://strawberry.rocks/docs/integrations/fastapi). Graphene: „a library that provides tools to implement a GraphQL API in Python using a code-first approach”, câmpuri declarate cu tipurile ei (`from graphene import ObjectType, String, Schema`; https://docs.graphene-python.org/en/latest/quickstart/). Ariadne: „describe your GraphQL API using Schema Definition Language” (https://ariadnegraphql.org/), deci schema-first. PyPI pe 3 noiembrie 2026: graphene 3.4.3, ariadne 1.1.1, strawberry-graphql 0.339.1 (https://pypi.org/pypi/graphene/json și celelalte; datele de încărcare nu au încăput în citire). Rulat (0.339.1): `@strawberry.type class Alert: title: str` generează `type Alert { title: String! }` (`strawberry.printer.print_schema`). „Graphene e mai vechi” e formularea punctului; nu am găsit o declarație de depreciere, doar versiunea 3.4.3.
- ✅ **Erori și HTTP**: spec §7.1.6: o eroare de execuție la o poziție lasă acea poziție `null` în `data` și intră în `errors`; o intrare din `errors` legată de un câmp are `path`; dacă un câmp non-null pică, `null` urcă la cel mai apropiat câmp nullable. GraphQL over HTTP §5.4.1: la o operație care rulează, serverul „SHOULD respond with a status code of `200 OK`”, chiar dacă apare o eroare de execuție; un rezultat fără `data` primește „an appropriate 4xx or 5xx” (cu `application/graphql-response+json`). graphql.org: „If a response contains a `data` key and its value is not `null`, then the server should respond with a `2xx` status code … This is the case even if the response includes errors, since HTTP does not yet have a status code representing 'partial success.'”; „For validation errors … the server will typically send a `400` status code, although some legacy servers may return a `2xx` status code when the `application/json` media type is used.” Rulat (0.339.1): `{ alert { title system { name } } }` cu `system` nullable și resolverul care ridică o excepție dă `{"alert": {"title": "t", "system": null}}` cu `errors` și `path` `["alert", "system"]`; cu `system_nn: System!` dă `data: null` (în schema de probă și `Query.alert` e `Alert!`, deci `null` urcă până la `data`); un câmp inexistent dă `data: null` și `path: null` (eroare de validare). „RED numără erorile după 5xx” e secțiunea `obs-03` din aplicație. Desfășurarea spune „recomandă 2xx” (SHOULD), nu „cere”.
- ✅ **Limite și autorizare** (https://graphql.org/learn/security/): „it's a good idea to limit the maximum depth of fields that a single operation can have”; complexitate: „If the combination of fields included in a request exceeds a maximum allowable cost per request, you may choose to reject the request outright”; „set appropriate timeout durations for requests”; liste „should be paginated to limit the maximum number of items that may be returned in a single request”; trusted documents: „create an allowlist of operations that can be executed against a schema”, „the server will only execute requests for known document IDs”, dar „trusted documents can't be used for public APIs because the operations sent by third-party clients won't known in advance”. Introspecția: „GraphQL APIs that only serve first-party clients may forbid introspection queries in non-development environments”, iar oprirea ei e „security through obscurity” și nu ajunge singură; pagina de introspecție: „Disabling introspection in production is common in order to reduce the API's attack surface.” Strawberry (https://strawberry.rocks/docs/extensions/query-depth-limiter): `from strawberry.extensions import QueryDepthLimiter`, `extensions=[QueryDepthLimiter(max_depth=10)]`. Rulat (0.339.1, `max_depth=3`): un query cu `alert { alerts { alerts { alerts { title } } } }` dă `'anonymous' exceeds maximum operation depth of 3` și `data: null` (Strawberry avertizează că instanțele din `extensions=[...]` sunt depreciate în favoarea clasei sau a unui factory; avertisment, nu eroare). Aritmetica `100 ** 3 = 1000000` și `20 ** 3 = 8000` e în exemplul rulat.
- ⚠️ **„Persisted queries”**: în punct și în GQL-02 înseamnă allowlist (doar documente cunoscute); graphql.org le numește „trusted documents”. Apollo Server are „Automatic Persisted Queries”, dar le prezintă doar ca optimizare de rețea („To improve network performance for large query strings”; https://www.apollographql.com/docs/apollo-server/performance/apq) și nu ca măsură de securitate. Desfășurarea descrie varianta allowlist, ca punctul, și nu pomenește APQ.
- ✅ **`@deprecated` și evoluția** (spec §3.13.3, ediția 2025): `directive @deprecated(reason: String! = "No longer supported") on FIELD_DEFINITION | ARGUMENT_DEFINITION | INPUT_FIELD_DEFINITION | ENUM_VALUE`; nu poate apărea pe argumente sau câmpuri de input obligatorii (non-null, fără valoare implicită). ⚠️ Pagina https://graphql.org/learn/schema/ încă arată definiția veche (`reason: String = …` `on FIELD_DEFINITION | ENUM_VALUE`); desfășurarea nu enumeră locațiile. Evoluție: pagina „Best Practices” de pe graphql.org rezumă lecția astfel: „Design and evolve a type system over time without versions”. Rulat (0.339.1): `severity: str = strawberry.field(deprecation_reason="Use severityLevel")` generează `severity: String! @deprecated(reason: "Use severityLevel")`.

**Erori de fapt în punctele fișei `graphql`**: niciuna găsită; punctele nu au fost modificate. Precizări, nu erori: la punctul 5, „de obicei cu HTTP 200” e SHOULD în draftul GraphQL over HTTP, iar cererile invalide primesc de obicei 400 cu `application/graphql-response+json` (serverele vechi cu `application/json` pot răspunde 2xx); la punctul 6, „introspecție oprită în producție” se aplică cu precădere la API-urile pentru clienți proprii și nu ține loc de autorizare (graphql.org), iar „persisted queries” înseamnă aici allowlist, nu APQ-ul Apollo; la punctul 4, Graphene 3.4.3 e încă publicat, „mai vechi” rămâne formularea punctului; la punctul 7, locațiile lui `@deprecated` din ediția 2025 a specificației includ și argumentele și câmpurile de input.
