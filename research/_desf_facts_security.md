## 32. Desfășurări `security`: SQL injection, deserializare, comenzi de sistem, SSRF, parole, JWT, OAuth2 / OIDC, autorizare la obiect, secrete, comparații și aleator, supply chain; comparațiile cu C++ (tichetul 16; verificat 3 noiembrie 2026)

Python rulat pe 3.13.16 (cele 9 blocuri `python` din `src/desf/security.md` rulează în `node tools/desf_examples.mjs`; cele 2 blocuri `text` sunt ieșiri reale, rulate la scriere). PyJWT 2.15.0, PyYAML 6.0.x, pip 26.2.1 și pip-audit 2.10.1 (instalat într-un venv temporar din PyPI). C++ compilat cu `g++ 13.3` (`-std=c++11`, `-std=c++17`) și `clang++ 18.1` (`-std=c++11`); faptele despre standard vin din draftul N4659 (timsong-cpp.github.io/cppwp/n4659) și din POSIX (cppreference răspunde 403 din mediul de lucru). OWASP, RFC-uri și docs citite pe 3 noiembrie 2026. Verificările din 1 noiembrie despre PyJWT, parolele OWASP și query-urile parametrizate sunt în secțiunea 12 (reverificate aici); Celery (JSON implicit) e în secțiunea 21, iar Keycloak (PKCE) în secțiunea 25.

- ✅ **OWASP Top 10:2025** (https://top10.owasp.org/2025): A01 Broken Access Control, A02 Security Misconfiguration, A03 Software Supply Chain Failures, A04 Cryptographic Failures, A05 Injection, A06 Insecure Design, A07 Authentication Failures, A08 Software or Data Integrity Failures, A09 Security Logging and Alerting Failures, A10 Mishandling of Exceptional Conditions. Pagina A01: „Maintaining its position at #1 in the Top Ten”; „Permitting viewing or editing someone else's account by providing its unique identifier (insecure direct object references)”; „Model access controls should enforce record ownership”; „Access control is only effective when implemented in trusted server-side code or serverless APIs”. Introducerea: „Server-Side Request Forgery (SSRF) has been rolled into this category.” (A01); A03 „is an expansion of A06:2021-Vulnerable and Outdated Components to include a broader scope of compromises”, iar pagina A03 spune că riscul „has grown in scope to include all supply chain failures, not just ones involving known vulnerabilities”; recomandă SBOM, dependențe tranzitive urmărite, pachete semnate. Introducerea spune „two new categories and one consolidation”, dar numește explicit nouă doar A10. Surse: https://top10.owasp.org/2025/0x00_2025-Introduction/, .../A01_2025-Broken_Access_Control/, .../A03_2025-Software_Supply_Chain_Failures/
- ⚠️ **„Categorie nouă” la punctul 11**: OWASP numără A03 printre „categoriile noi” ale ediției, dar o descrie ca extindere a lui A06:2021. Punctul rămâne neschimbat (nu e o eroare); desfășurarea spune „A03, care extinde A06:2021”.
- ✅ **OWASP API Security Top 10:2023, API1 BOLA** (https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization): „Every API endpoint that receives an ID of an object, and performs any action on the object, should implement object-level authorization checks”; verificarea se face „in every function that uses an input from the client to access a record in the database”; recomandă ID-uri aleatoare ca GUID-uri, dar ca măsură separată de „a proper authorization mechanism”, deci UUID-urile nu înlocuiesc verificarea. Rulat: `get(1, 42)` întoarce `'factura 42'`, iar `get(1, 43)` ridică `PermissionError`.
- ✅ **DRF, permisiuni pe obiect** (https://www.django-rest-framework.org/api-guide/permissions/): `has_object_permission` rulează doar după ce `has_permission` a trecut; „generic views will not automatically apply object level permissions to each instance in a queryset”; pentru liste „you'll need to filter the queryset separately”; la un `get_object()` suprascris chemi tu `check_object_permissions`.
- ✅ **SQL injection** (https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html): prima apărare = prepared statements cu query-uri parametrizate; „Parameter markers represent data values, not table names, column names, or SQL keywords such as ASC and DESC”, deci nume și direcții se mapează pe o listă de valori ale aplicației; escaping-ul manual e „STRONGLY DISCOURAGED”. Rulat (`sqlite3`, `:memory:`): `select 1 where 'a'='{n}'` cu `n = "x' OR '1'='1"` întoarce `[(1,)]`, iar `select 1 where 'a'=?` cu `[n]` întoarce `[]`. Django: la `raw()` „Do not use string formatting on raw queries or quote placeholders in your SQL strings!”, parametrii merg în `params` cu `%s` (https://docs.djangoproject.com/en/5.2/topics/db/sql/). `%s` e marcajul `psycopg` (secțiunea 27); `text()` cu `:nume` (punctul 11 din fișa sqlalchemy).
- ✅ **pickle și YAML** (https://docs.python.org/3/library/pickle.html): „The `pickle` module is not secure. Only unpickle data you trust. It is possible to construct malicious pickle data which will execute arbitrary code during unpickling”; `__reduce__` întoarce un tuplu cu un apelabil și argumentele lui; docs recomandă JSON pentru date nesigure și semnarea cu `hmac` doar ca dovadă că datele nu au fost modificate. Rulat: o clasă cu `__reduce__` întors `(print, ("rulat",))` afișează `rulat` la `pickle.loads`. PyYAML: „It is not safe to call `yaml.load` with any data received from an untrusted source!”; `safe_load` „cannot construct an arbitrary Python object” (https://pyyaml.org/wiki/PyYAMLDocumentation). Rulat (6.0.x): `yaml.load("a: 1")` ridică `TypeError: load() missing 1 required positional argument: 'Loader'`; `!!python/object/apply:print ['x']` afișează `x` cu `Loader` și cu `UnsafeLoader`, dar ridică `ConstructorError` cu `FullLoader` și cu `SafeLoader`. Celery: `task_serializer` implicit JSON din 4.0 (secțiunea 21; CEL-11).
- ✅ **`subprocess`** (https://docs.python.org/3/library/subprocess.html): „Unlike some other popen functions, this library will not implicitly choose to call a system shell. This means that all characters, including shell metacharacters, can safely be passed to child processes. If the shell is invoked explicitly, via `shell=True`, it is the application's responsibility to ensure that all whitespace and metacharacters are quoted appropriately”; `shlex.quote` poate fi folosit „on some platforms”. Rulat: `check_output("echo " + "a; echo X", shell=True)` dă `b'a\nX\n'`, iar `check_output(["echo", "a; echo X"])` dă `b'a; echo X\n'`.
- ✅ **C++: comenzi** (compilat cu `g++ -std=c++17`, `g++ -std=c++11`, `clang++ -std=c++11`): `std::system(("echo " + name).c_str())` cu `name = "a; echo X"` afișează `a` și `X` pe linii separate; `fork` + `execvp({"echo", name})` afișează `a; echo X`. POSIX: `system()` „shall pass the string pointed to by command to that command processor” (se comportă ca `sh -c`); `execvp`: `argv` e „an array of character pointers to null-terminated strings”, ultimul membru trebuie să fie `NULL`, iar fișierul se caută în `PATH` doar dacă nu conține `/` (https://pubs.opengroup.org/onlinepubs/9799919799/functions/system.html, .../exec.html). `execvp` și `fork` sunt POSIX, nu standard C++ (standardul are doar `std::system`).
- ✅ **SSRF** (https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html): „Match the host against an allowlist, and build the request yourself”; „Deny-lists are bypass-prone. Prefer allow-lists.”; „Disable the support for the following of the redirection in your web client”; „Domain allowlisting alone does not prevent DNS rebinding”, iar „A second, unchecked DNS lookup between validation and connection can bypass these checks”; blocul minim include `169.254.169.254` (AWS, GCP, Azure); „IMDSv2 is an additional defense-in-depth mechanism for AWS that mitigates some of the instances of SSRF.” AWS (https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/configuring-instance-metadata-service.html): IMDSv2 e orientat pe sesiune: un `PUT` către `/latest/api/token` (cu header-ul `X-aws-ec2-metadata-token-ttl-seconds`) întoarce un token, pus apoi în `X-aws-ec2-metadata-token` la `GET`; implicit „you can use either IMDSv1 or IMDSv2, or both”; răspunsul la `PUT` are hop limit 1, iar `PUT`-urile cu `X-Forwarded-For` se resping. „Multe SSRF-uri fac doar `GET`” e raționament, nu citat. Rulat (3.13): `ipaddress.ip_address(a).is_global` dă `True` pentru `8.8.8.8` și `False` pentru `169.254.169.254`, `10.0.0.5`, `127.0.0.1`, `::1`, `::ffff:127.0.0.1`, `::ffff:169.254.169.254`, `100.64.0.1`, `fd00:ec2::254` și `0.0.0.0`; `::ffff:8.8.8.8` dă `True`.
- ✅ **Parole** (https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html): „Use Argon2id with a minimum configuration of 19 MiB of memory, an iteration count of 2, and 1 degree of parallelism”; scrypt (N=2^17, r=8, p=1) dacă Argon2id nu e disponibil; bcrypt doar pentru sisteme vechi, factor ≥ 10, „maximum length input length of 72 bytes”; PBKDF2 pentru FIPS-140, „PBKDF2-HMAC-SHA256: 600,000 iterations”; „A salt is a unique, randomly generated string”, pe fiecare credențial. Django (https://docs.djangoproject.com/en/5.2/topics/auth/passwords/): implicit „PBKDF2 algorithm with a SHA256 hash”, formatul stocat `<algorithm>$<iterations>$<salt>$<hash>`, Argon2 se adaugă prin `PASSWORD_HASHERS`; docs nu dau numărul de iterații. Rulat: `hashlib.pbkdf2_hmac("sha256", b"pw", salt, 600_000)` durează ~0,45 s și dă același rezultat pentru același salt, altul pentru alt salt (`True`, `False`). SHA-256: ~22 GH/s pe un RTX 4090 în hashcat 7.0.0 (benchmark de pe forumul hashcat, https://hashcat.net/forum/post-63595.html), de unde „miliarde de ori pe secundă”.
- ⚠️ **bcrypt la punctul 5**: punctul spune „Argon2id sau bcrypt”; OWASP pune scrypt înaintea lui bcrypt, care e doar pentru sisteme vechi. Precizare, nu eroare; desfășurarea reproduce ordinea OWASP.
- ✅ **JWT** (RFC 7515, https://www.rfc-editor.org/rfc/rfc7515: JWS „provide integrity protection”, payload-ul e `BASE64URL(JWS Payload)`, confidențialitatea e în JWE; RFC 8725, https://www.rfc-editor.org/rfc/rfc8725: „Libraries MUST enable the caller to specify a supported set of algorithms” (§3.1), „none” doar când JWT-ul e protejat altfel (§3.2), `iss` (§3.8) și `aud` (§3.9) se validează). Rulat (PyJWT 2.15.0): fără `require`, un token fără `exp` e acceptat; cu `options={"require": ["exp"]}` ridică `MissingRequiredClaimError`; un token cu `aud` decodat fără `audience=` ridică `InvalidAudienceError`; cu `issuer="me"` și `iss: "evil"` ridică `InvalidIssuerError`, dar fără `issuer=` tokenul cu `iss: "evil"` trece (`iss` nu se verifică singur); un token `alg: none` cu `algorithms=["HS256"]` ridică `InvalidAlgorithmError`; `base64.urlsafe_b64decode(x + b"==")` pe a doua parte a unui token dă payload-ul în clar, fără cheie. Keycloak: `/realms/{realm-name}/protocol/openid-connect/certs` („certificate endpoint”) și `/realms/{realm-name}/.well-known/openid-configuration` (https://www.keycloak.org/securing-apps/oidc-layers).
- ✅ **OAuth2, OIDC, PKCE** (RFC 7636, https://www.rfc-editor.org/rfc/rfc7636: `code_challenge = BASE64URL-ENCODE(SHA256(ASCII(code_verifier)))`, verifier de 43–128 de caractere, anexa B cu verifier `dBjftJeZ4CVP-mB92K27uhbUJU1p1r_wW1gFWFOEjXk` și challenge `E9Melhoa2OwvFrEMTJguCHaoeK1t8URWbuGJSstw-cM`; RFC 9700, https://www.rfc-editor.org/rfc/rfc9700: „Public clients MUST use PKCE” (§2.1.1), „clients SHOULD NOT use the implicit grant” (§2.1.2), password grant „MUST NOT be used” (§2.4); OpenID Connect Core 1.0, https://openid.net/specs/openid-connect-core-1_0.html: „a simple identity layer on top of the OAuth 2.0 protocol”, ID Token = JWT cu claim-uri despre autentificare, „OpenID Connect requests MUST contain the openid scope value”). Rulat: derivarea din RFC dă `E9Melhoa2OwvFrEMTJguCHaoeK1t8URWbuGJSstw-cM` (primele 9 caractere `E9Melhoa2`). „ID token pentru client, access token pentru API” e convenția OIDC, nu un citat; Client Credentials între servicii: RFC 6749 §4.4. Frontend: punctul 12 din fișa frontend (secțiunea 25).
- ✅ **Secrete** (https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html): secretele nu se pun cu „docker ENV or docker ARG commands” („can easily leak with the container definitions”); variabilele de mediu sunt ultima soluție („not recommended unless the other methods are not possible”); „Secrets must have the minimum privileges assigned to them”; la un secret expus: revocare imediată, apoi rotire. GitHub (https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository): „you need to revoke and/or rotate that secret”; rescrierea istoricului nu elimină commit-urile din clone și fork-uri. Docker Swarm (https://docs.docker.com/engine/swarm/secrets/): „the decrypted secret is mounted into the container in an in-memory filesystem”, implicit la `/run/secrets/<secret_name>`; nu se pun ca variabile de mediu pentru că „environment variables can unintentionally be leaked”. Rulat (git într-un director temporar): după `git rm .env` și un commit, `git log -p | grep DB_PASS` arată `-DB_PASS=hunter2` și `+DB_PASS=hunter2`, deci parola rămâne în istoric.
- ✅ **`hmac.compare_digest` și `secrets`** (https://docs.python.org/3/library/hmac.html, https://docs.python.org/3/library/secrets.html, https://docs.python.org/3/library/random.html): `compare_digest` „uses an approach designed to prevent timing analysis by avoiding content-based short circuiting behaviour”; argumentele au același tip, `str` doar ASCII sau bytes-like; la lungimi diferite „a timing attack could theoretically reveal information about the types and lengths of a and b—but not their values”. `random`: „should not be used for security purposes”, Mersenne Twister „completely deterministic … completely unsuitable for cryptographic purposes”; același seed reproduce secvența; `secrets`: „should be used in preference to the default pseudo-random number generator in the `random` module”; `token_hex(nbytes)` dă 2 caractere hex pe octet; `DEFAULT_ENTROPY` „is subject to change at any time” (rulat pe 3.13.16: 32 de octeți, `token_urlsafe()` de 43 de caractere, `token_hex(16)` de 32 de caractere). Rulat: `random.seed(7)` repetat dă același `random.random()` (`True`); `compare_digest("é", "é")` ridică `TypeError: comparing strings with non-ASCII characters is not supported`; `compare_digest(b"abc", b"abcd")` dă `False`.
- ✅ **C++: aleator și comparații** (compilat cu `g++ -std=c++11` / `-std=c++17` și `clang++ -std=c++11`): `std::mt19937 g1(7), g2(7)` dau aceeași primă valoare; `std::random_device` dă valori diferite între instanțe, iar `entropy()` a întors 32 pe libstdc++ din mediul de lucru. Standardul ([rand.device], N4659): „A random_device uniform random bit generator produces nondeterministic random numbers.”; „If implementation limitations prevent generating nondeterministic random numbers, the implementation may employ a random number engine.”; `entropy()`: „If the implementation employs a random number engine, returns 0.0.” `memcmp` e doar declarat în `<cstring>` („the same as the C standard library header <string.h>”), iar în draft nu apare nicio garanție de timp. Nu am găsit nicio cerință de timp constant pentru `memcmp` sau `std::string::operator==`; „pot ieși la prima diferență” e permisiunea standardului, nu o măsurare. Biblioteca de criptografie nu e numită în desfășurare (nu am verificat paginile OpenSSL).
- ✅ **Supply chain** (https://pip.pypa.io/en/stable/topics/secure-installs/): „Specifying `--hash` against any requirement will activate this mode globally”; „Requirements must be pinned (either to a URL, filesystem path or using `==`)”; „If there is a dependency that is not spelled out and hashed in the requirements file, it will result in an error.” Rulat (pip 26.2.1): `pip install --dry-run --require-hashes -r r.txt` cu `requests==2.33.1` fără hash ridică „ERROR: Hashes are required in --require-hashes mode, but they are missing from some requirements” și listează hash-ul real. pip-audit (https://pypi.org/project/pip-audit/, versiunea 2.10.1 din 10 iunie 2026): „a tool for scanning Python environments for packages with known vulnerabilities”, folosește Python Packaging Advisory Database prin API-ul JSON PyPI (OSV ca alternativă), `-r requirements.txt`. Rulat: `pip-audit -r req.txt --no-deps --disable-pip` pe `flask==0.12` raportează 8 vulnerabilități, primul rând `flask 0.12 PYSEC-2019-179 1.0` (ieșirea reală repetă unele rânduri; desfășurarea arată primul și `...`). GitLab Dependency Scanning: „identifies known security vulnerabilities in your project's dependencies”, cere nivelul Ultimate (https://docs.gitlab.com/user/application_security/dependency_scanning/); desfășurarea nu pomenește nivelul.

**Erori de fapt în punctele fișei `security`**: niciuna găsită; punctele nu au fost modificate. Cele 11 puncte au fost recitite față de sursele de mai sus și față de rulări. Precizări, nu erori: la punctul 2, `yaml.load` e periculos cu `Loader` / `UnsafeLoader` (PyYAML 6 cere argumentul `Loader`, iar `safe_load` și `FullLoader` au respins `!!python/object/apply:print`); la punctul 5, OWASP pune scrypt înaintea lui bcrypt, rezervat sistemelor vechi; la punctul 6, „JWT e semnat, nu criptat” e valabil pentru JWS (forma uzuală), JWE există; PyJWT verifică `exp` doar dacă există în token și `iss` doar cu `issuer=`; la punctul 11, OWASP numește A03 „categorie nouă”, dar o descrie ca extindere a lui A06:2021, iar GitLab Dependency Scanning cere Ultimate.
